# Domain Intel

This tier sits **alongside** the Global Wiki, not inside it. It holds
agnostic capture-lifecycle overlays distilled from real-world federal
capture practice. Anything here must be safe to share with an outside
reviewer — no company names, no proprietary identifiers, no internal
URLs.

## Why a separate tier

| Tier | Provenance | Lifecycle |
|---|---|---|
| `knowledge/global_wiki/` | Third-party doctrine (Shipley, FAR/DFARS) seeded from `theseus/src/ontology/knowledge/` | Regenerated by `scripts/seed_global_wiki.py` |
| `knowledge/domain_intel/` | Hand-curated agnostic overlays — milestone gates, briefing flows, decision frameworks adapted from industry practice | Hand-edited; never regenerated |
| `knowledge/pursuits/<slug>/wiki/` | Per-opportunity intel synthesized from raw artifacts | Per-RFP |

Keeping them separate means a reviewer can grep `domain_intel/` and
verify it carries zero proprietary content, independent of what lives
in `global_wiki/` or `pursuits/`.

## Current contents

- `milestones/` — MS1–MS4 capture decision-gate model with promotion
  criteria. (Authored in Phase 021.)

## Authoring rules

1. No company names, internal team names, or trademarked product names.
2. No internal URLs (SharePoint, Confluence, intranet).
3. Briefing-template language must be agnostic — replace
   "Salesforce ID" with "Opportunity ID (CRM)", etc.
4. When adapting from a proprietary source, paraphrase. Do not paste
   verbatim text that originated in a CONFIDENTIAL document.
5. Files use the same `WikiEngine`-compatible Markdown + YAML
   frontmatter as the Global Wiki, so they render in the UI via a
   second `WikiEngine` instance pointed at `CONFIG.domain_intel_dir`.
